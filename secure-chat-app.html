What it demonstrates

Applied cryptography in a working chat system.

This project combines networking, key management, authenticated encryption, and a usable desktop interface. Each client owns its RSA identity, exchanges public keys through the relay, wraps a fresh AES session key, and sends messages that the server can route but cannot decrypt.

The result is a portfolio-ready educational build: small enough to audit, but complete enough to show practical security decisions across multiple modules.

System design

How the message flow works

01

Key Identity

Clients generate or load RSA-2048 keypairs and expose public key fingerprints in the GUI.

02

Relay Handshake

The TCP server coordinates client connections and forwards public keys without owning private material.

03

Session Encryption

AES-256-GCM encrypts message bodies with unique nonces and authentication tags for integrity checks.

04

Framed Transport

A shared protocol packs message type and payload length before sending bytes across the socket.

Implementation

Concrete engineering pieces

Client and GUI

Tkinter drives connection state, message input, chat display, and public key fingerprint visibility while the client module handles socket communication.

Cryptography module

RSA-OAEP protects the session key, while AES-GCM handles authenticated message encryption and tamper detection.

Server relay

The server manages multiple clients, forwards protocol messages, and stays intentionally blind to plaintext content.

client/crypto.py 
def encrypt_message(session_key, plaintext):
    aesgcm = AESGCM(session_key)
    nonce = os.urandom(12)
    ciphertext = aesgcm.encrypt(
        nonce,
        plaintext,
        associated_data=None
    )
    return nonce, ciphertext
